# deadWall

A Windows-first desktop network monitor and application firewall, built in Rust.
Traffic opens in a chart-first workspace with top navigation and Timeline, Table, and IP map views.
The inspector shows separate CPU, RAM, and GPU sparklines. RAM also shows used and
total physical memory.

## Build and run

The [Windows release](https://github.com/deadcodeXO/deadWall/releases/latest)
includes an x64 installer. Install Npcap separately for packet capture.

The desktop frontend is the Vite/React template generated by [Tauri UI](https://tauriui.vercel.app/).
It uses shadcn/ui and connects to the same Rust monitoring, history, GeoIP and firewall modules
as the original egui app. All desktop assets and GeoIP data are bundled locally.

Install Bun and a current Rust toolchain. On Windows use the MSVC toolchain, Visual Studio
Build Tools with the Desktop development with C++ workload, and Microsoft Edge WebView2.
Install [Npcap](https://npcap.com/#download) for packet capture. Interface counters work
independently of Npcap.

```powershell
cd desktop
bun install --frozen-lockfile
bun run tauri dev
bun run tauri build
```

To build the executable without an installer:

```powershell
bun run build
cargo build --manifest-path src-tauri/Cargo.toml --release --locked --features custom-protocol
```

The executable is `desktop/src-tauri/target/release/deadwall-tauri.exe` from the repository root.
The original egui frontend is still available with `cargo run --release --locked` from the repository
root. Either frontend reads the same local history. Run one at a time to avoid recording twice.

## Use

- **Traffic** opens on a usable packet adapter when one is available. In Settings,
  choose another adapter or switch to system interface counters. Packet totals
  cover classified IP traffic and can differ from adapter counters.
- **Time machine** provides a two-minute live view, one hour, one day, one week,
  and all recorded time. Click a graph point or historical aggregate to see App,
  Host, Traffic type, Connection, or Country usage. Historical charts pan and
  zoom. CSV export streams individual bandwidth samples for the selected range.
- **IP map** shows offline country estimates for observed traffic and manual IPv4 or IPv6 lookups. Clicking a
  map dot filters the usage table. IP resolution and the map are offline. See
  [data and font notices](assets/THIRD_PARTY_NOTICES.txt).
- **Usage** shows per-process CPU, RAM, I/O, and available GPU counters. Total
  CPU is system-wide. Windows GPU utilization is the busiest observed engine.
  The process GPU value is that process's busiest observed engine, and a missing
  counter appears as unavailable. Per-process I/O is the operating system's
  process I/O delta. System Disk I/O uses the physical-disk performance counter.
- **Things** shows the OS neighbor cache on Windows and Linux. On Windows, select
  a directly connected IPv4 address and scan to send local ARP requests. The
  sweep covers no more than the local /24 and respects smaller subnets.
- **Alerts** records first attributed application traffic, new neighbors,
  neighbor MAC changes, suspected Wi-Fi impersonation, DNS and Windows proxy
  changes, watched executable and hosts-file changes, inbound traffic on the
  RDP port, and activity after Windows input inactivity. On Ethernet, deadWall
  also flags conflicting live ARP claims for the same IPv4 address. MAC changes
  can reflect legitimate address reassignment. The Wi-Fi check flags alternate
  security settings advertised under the connected SSID when Windows exposes
  them, including an open copy of a secured network. Add one IP per line to
  `suspicious-ips.txt` beside the database and restart for local watchlist alerts.
- **Firewall** manages bidirectional executable block rules in Windows Defender
  Firewall for selected Domain, Private, and Public profiles. Search running processes and right-click a row to manage its application block. Click an executable
  in a usage table to open its controls. Enabling app rules or Lockdown requires
  an elevated Windows session. Remove manual rules using the same category selection.
  Saved firewall profiles hold named lists of executables and Windows categories.
  Apply or remove the entire profile from Firewall. Profiles can overlap, and
  removing one leaves manual rules and the rules of other profiles in place.
  Ask to Connect uses an elevated Windows Filtering Platform session to block
  unapproved non-loopback outbound connections across profiles. Allowing a request
  lets the application retry. Decisions end when the session closes, and existing
  Windows firewall policy still applies. Use Lockdown and Ask to Connect from the
  local desktop because they can interrupt DNS, DHCP, and remote access.
- **Live IP map** groups recently observed remote IPs by estimated country. Hover
  for the latest endpoint, application, traffic counters, and observation time.
  Click a country marker to keep its recent IPs visible. Switch off Live
  connections to browse the selected range's aggregate country totals.
- **Geographic filtering** in Settings accepts continents, ISO country codes,
  and IPv4 or IPv6 CIDRs. On Windows, Apply installs a bidirectional block
  policy for matching remote addresses across all applications. The rules use
  the bundled country database, require elevation, and end when deadWall closes.
  The draft survives restart and can be reapplied. Turn off clears the policy.
- **Appearance** offers Nord, Dracula, Catppuccin, Rosé Pine, Tokyo Night, Gruvbox,
  Solarized, Everforest, Kanagawa, and GitHub. The sun/moon button switches
  between light and dark variants of the selected palette.
- **Minimize to tray** keeps capture running when the main window is minimized. The tray menu provides Show deadWall and Quit.
- **Display settings** include the live map activity window, horizontal
  timeline guides, and the system inspector preference.
- **Local-only operation** keeps capture, history, GeoIP, and security checks on this machine. The app starts no remote monitoring listener and uses no cloud reputation services.
- **Mini graph** opens an always-on-top live view. The legacy Settings page includes GitHub Dark,
  Nord, Tokyo Night, and Daylight palettes. The round sun/moon button switches between Daylight and the most recent dark palette.

Settings displays the local SQLite path. Windows uses
`%LOCALAPPDATA%\deadWall\history.sqlite3`; macOS uses
`~/Library/Application Support/deadWall/history.sqlite3`; Linux uses
`$XDG_DATA_HOME/deadWall/history.sqlite3` or `~/.local/share/deadWall/history.sqlite3`.
History is retained until you remove it. SQLite stores aggregate bytes, endpoint and
application usage, and alert metadata. The capture engine keeps packet payloads
out of storage. CSV exports are written beside the database.

## Architecture and implementation phases

| Phase | Modules | Implementation |
| --- | --- | --- |
| 1 · Capture and desktop | `pcap`, `traffic`, `engine`, `ui` | Non-promiscuous Npcap/libpcap capture, bounded flow accounting, native live graph, OS counter fallback |
| 2 · History and attribution | `history`, `processes`, `hardware`, `geo` | SQLite WAL and a separate history reader, Windows socket owner snapshots, PDH, CSV, and offline country mapping |
| 3 · Security and LAN | `watch`, `devices`, `firewall`, `profiles`, `ask` | Windows firewall COM rules, dynamic WFP approval mode, device inventory, ARP discovery, and persisted alerts |
| 4 · Desktop tools | `ui` | Themes, inspector and resource sparklines, floating graph |

`eframe` and `egui_plot` give the app a Rust desktop UI without a WebView. Windows
uses WGPU/Direct3D 12 and the portable desktop backend uses OpenGL. The capture
backend loads the platform libpcap ABI through `libloading`, and `etherparse`
decodes Ethernet and IP headers. `sysinfo` supplies portable interface and process
counters, while Windows IP Helper associates sockets with PIDs and PDH supplies
hardware counters. Attribution is best-effort, especially for short-lived sockets,
shared UDP ports, and traffic observed between socket snapshots. Entries without
a reliable match are shown as unknown.

`rusqlite` and bundled SQLite handle durable local history. Application logic and
UI are written in Rust. The build includes SQLite's C library and uses native
capture libraries and OS APIs where necessary. Dedicated threads handle
synchronous capture, history reads, and opt-in network work, so the application
does not require a Tokio runtime. The monitor transfers one-second snapshots to
the UI and keeps heavy history queries off the capture thread.

The Windows capture dashboard was exercised against an installed Npcap driver,
including observed per-app traffic. Live elevated firewall enforcement and Wi-Fi anomaly detection on Wi-Fi hardware require platform verification.
